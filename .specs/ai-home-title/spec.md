# AI Home Title Spec

## Summary

Replace the static Home screen title copy with a short, friendly, personalized, context-aware title generated by the garden AI layer.

Current title pattern is static, e.g. `Good morning, back garden is waking up.` The new title should adapt to the garden setup, weather context, plant state, recent activity, and time of day while staying brief and calm.

## Goals

- Generate a short Home title/headline that feels personal and garden-aware.
- Use available local context:
  - garden name
  - garden week / creation date
  - weather summary and USDA zone when available
  - plant count and attention items
  - recent photo/activity signals
  - time of day
- Keep tone friendly, warm, and specific without being overly cute.
- Keep copy short enough for the existing hero layout.
- Provide a deterministic local fallback when AI is unavailable, slow, disabled, or missing credentials.
- Avoid blocking Home screen rendering on AI text generation.
- Avoid sending unnecessary private/raw data; pass a compact title context only.

## Non-goals

- No chat UI changes.
- No full daily briefing feature yet.
- No push notifications/reminders.
- No long-form generated paragraphs in the hero title.
- No production-only dependency on an AI provider for rendering Home.

## UX requirements

### Title shape

The title should be one short line or two short visual lines in the existing hero area.

Target examples:

- `Back Garden is ready for a quick look.`
- `A warm morning for the tomatoes.`
- `Week 3 in Back Garden — check the thirsty ones.`
- `Jersey City looks good for a garden pass.`
- `Two plants need you today.`

### Tone

- Friendly and personalized.
- Specific when context supports it.
- Calm, not alarmist.
- Avoid cheesy over-personification.
- Avoid repetitive greetings if better context exists.

### Length

- Target: 45 characters or fewer.
- Hard cap: 70 characters after trimming.
- Prefer no more than 2 display lines in the current layout.

### Context priority

When selecting title content, prioritize:

1. Urgent/timely plant attention, if present.
2. Weather context that materially affects gardening today.
3. Recent garden activity / garden week milestone.
4. Gentle generic greeting using garden name.

## Architecture proposal

Add a small frontend view-model/service boundary:

- `HomeTitleContextBuilder`
  - Builds compact input from local Home data and weather/setup state.
- `HomeTitleService`
  - Returns a title from AI when available.
  - Falls back to deterministic local title on timeout/error/unavailable provider.
- `homeTitleFallback`
  - Pure helper for stable offline titles.

Preferred first implementation:

- Start with a deterministic context-aware local title helper in the frontend.
- If adding AI immediately, route through the existing backend garden-agent API rather than calling provider SDKs from the app.
- Keep AI timeout short and never block Home rendering; update title when generated text returns.

## AI prompt guardrails

If using backend AI generation, prompt should request:

- One short home-screen title only.
- Friendly, personalized tone.
- No markdown, emojis, quotes, or trailing punctuation unless natural.
- No claims not supported by supplied context.
- Return fallback-safe plain text only.

## Fallback behavior

Fallback title examples:

- attention item exists: `{count} plants need a quick look.`
- weather available: `{gardenName} has a {condition} day ahead.`
- garden week available: `Week {n} in {gardenName}.`
- generic: `{gardenName} is ready for a look.`

## Testing

Add pure helper tests for:

- attention-priority title selection
- weather title selection
- garden-week title selection
- generic fallback
- length clamping/sanitization
- no empty title for missing context

If backend route/prompt is added, add API tests for:

- success
- provider failure fallback
- timeout/failure non-blocking behavior

## Risks

- AI text may be too long or too whimsical; enforce client-side sanitization and fallback.
- Home screen could feel jumpy if title changes after load; prefer stable fallback first, then one smooth update if AI returns.
- Weather/plant context can be stale; phrase generated titles gently and avoid precise unsupported recommendations.

## User clarification

The title can be AI-driven and does not need to regenerate every time the app opens. It should not make Home feel slow. The UI may intentionally acknowledge that it is being generated, for example with a subtle animated/loading title state, as long as the rest of Home loads immediately.

## Caching / freshness policy

Recommended behavior:

- Store the latest accepted AI title locally with:
  - generated title
  - generated timestamp
  - compact context hash/signature
- Reuse the cached title on app open when the garden context has not materially changed and the title is still fresh.
- Suggested freshness window: same local day, or until context changes materially.
- Material changes that should request a new title:
  - new photo/plant added
  - attention item count changes
  - weather condition changes meaningfully
  - garden setup name/location changes
  - garden week changes
- If cached title exists, show it immediately while optionally refreshing in the background.
- If no cached title exists, show an animated/loading title placeholder briefly while generation runs, then replace it when ready.
- If generation exceeds a short timeout, keep/show deterministic fallback and retry later.

## Loading UX

Acceptable first-run/loading title states:

- `Reading the garden…`
- `Looking over today’s garden…`
- `Finding the right note…`

Animation should be subtle:

- gentle opacity pulse
- shimmer/skeleton text line
- cycling ellipsis

The loading state should affect only the title area. Weather, plant cards, gallery, and navigation must remain usable.

## Tone anchor

Preserve the gentle “your deck/garden is waking up” feeling from the current title. The new AI title should feel like a small living-garden observation, not a generic dashboard headline.

Good tone examples:

- `Your deck is waking up.`
- `Back Garden is waking up slowly.`
- `Your garden looks ready for a look.`
- `A quiet morning in Back Garden.`
- `The tomatoes are asking for a glance.`

Avoid:

- overly corporate status copy, e.g. `Garden dashboard updated`
- overly dramatic copy, e.g. `Urgent garden intervention needed`
- overly whimsical copy that feels fake or cloying
- over-specific claims not grounded in context

## Context awareness details

The title should pay explicit respect to time of day and the current state of the garden when those signals are available.

Time-of-day guidance:

- Morning: waking up, first look, gentle start, watering check.
- Afternoon: sun/heat, quick check-in, shade/watering awareness.
- Evening: winding down, last look, tomorrow’s care.
- Night: quiet, restful, no urgent language unless attention items exist.

Garden-state guidance:

- If attention items exist, mention them gently and specifically.
- If weather is hot/dry/windy/rainy, let that shape the title when useful.
- If the garden is newly created, make the title encouraging and first-step oriented.
- If recent photos/plants were added, acknowledge momentum.
- If nothing needs action, choose calm observation copy rather than inventing urgency.

Examples:

- Morning + no urgent items: `Back Garden is waking up.`
- Afternoon + hot weather: `A warm afternoon for a quick soil check.`
- Evening + attention item: `One plant wants a last look tonight.`
- New garden: `Your garden is ready for its first note.`
- Recent activity: `Back Garden has new things to remember.`

## Contextuality requirement

Highly contextual output is a core requirement, not a nice-to-have. The title should be generated from the most meaningful current signals rather than randomly selecting pleasant copy.

The system should build a compact context packet that includes, when available:

- garden name and location
- local time-of-day bucket
- garden age/week
- current weather condition, temperature, precipitation/wind/heat signals
- USDA zone if relevant
- plant count
- plants needing attention and their status/next-action labels
- latest photo date and recent activity count
- newly added plant/photo signals
- whether the garden is brand new or established

Generation should prefer specificity:

- Better: `A warm afternoon for Basil and Mint.`
- Worse: `Your garden is looking nice.`
- Better: `Back Garden is waking up after rain.`
- Worse: `Good morning, gardener.`

If context is thin or unavailable, fallback to the tone anchor rather than hallucinating detail.
